## Composition

`src/App.tsx` composes project controls, timeline, notes, and queue. `src/app/controller.ts` owns synchronous current domain state, serialized transitions, target-scoped editor snapshots, autosave, and failure feedback. Module READMEs document integration seams. `src/persistence/` owns the native repository/revision writer; `src-tauri/src/persistence.rs` owns validated project folders, atomic writes, and narrow recording asset approval. Each project contains `wavnotes.json` and its copied `recording.wav`.

The native close listener must register before project access is enabled. `src-tauri/src/quit_guard.rs` routes macOS termination and Tauri exit requests through guarded window close; `safeToLeave` flushes and saves or asks before discarding. Force Quit is outside normal protection.

## Persisted project contract (`project.ts`)

- `ProjectData` is version 1 JSON. `id` and annotation IDs are stable opaque strings, globally unique in their respective scope; create them once (e.g. UUID) and never derive them from time or order. `annotations` is ordered independently of timestamps. Multiple annotations may share or overlap times. `recording.relativePath` must resolve within the project folder and refer to the project's copied WAV; reject absolute paths, traversal, unsupported versions, missing recordings and malformed data on open. Path separators/validation are the persistence owner's responsibility.
- `Annotation.anchor` is a discriminated `point` or `range`. All times are finite seconds relative to the recording, from zero through its known finite nonnegative duration. Ranges are strictly increasing. `isValidAnchor` checks these invariants; capture/edits must be validated when duration is available. No musical snapping. Labels/excerpts are derived, not stored.
- `NoteDocument` is Editor.js `OutputData`; each annotation and `projectNote` has one document (an empty document can use `{ blocks: [] }`). Do not convert canonical content to Markdown. Pending state is independent of note content.
- `pendingAnnotationIds` is the sole persistent pending-status source and is ordered by capture, not time or annotation display order. IDs must be unique and reference existing annotations. Completing removes an ID; skip does not. Preserve partial notes and queue ordering across save/reopen. On load initialize review as `inactive` and do not seek or open a note automatically. Review-pass skips, active item, and resume position are transient, not project JSON.

## A: pure domain and review (`domain.ts`)

`DomainReducer` takes `DomainState` and a `DomainAction`, and returns a new state plus ordered `DomainEffect` instructions; it performs no I/O. Composition supplies a fresh annotation ID, transport playing state and positions. `selectedNote` is distinct from the review current item. Create an empty Editor.js document on capture. `capture-point`/`annotate-selection` append to both annotations and pending IDs. While playing they do not seek, focus, or interrupt. While paused they open the new pending item immediately, without losing other pending items. A temporary waveform selection alone is not an action creating an annotation.

Both captures require known duration; range capture and direct queue selection also require live position. After a skipped-only pass, ordinary pauses defer automatic review until a new capture, but natural non-looping recording end still reviews pending work.

`user-paused` and non-looping `playback-ended` enter review only when pending exists and no pass is already active; remember the listening position, seek to the first pending item in capture order, and open it. During active review ordinary play/pause and end events must not switch current items. `select-note` opens a note without seeking or changing review; explicit `select-queue-item` chooses a pending review item. `done-next` completes regardless of content and advances to the next eligible item. `skip` keeps pending and excludes the item from the current pass. Once the pass has no eligible items, return `offer-review-result` with pending count and saved resume position. `review-pending` explicitly starts a fresh pass; `resume-listening` seeks to the saved position without starting playback. Actions on invalid/missing IDs should be safe no-ops.

Delete retains an undo snapshot with annotation and its annotation/pending indexes; undo restores content, timing and pending position. Selection and active-review reconciliation after deleting a current item must not silently complete any other item. `update-anchor` validates bounds; `update-note` targets the specified note, never whichever editor happens to be visible at callback time. Opening an existing project builds initial state from its project JSON with an inactive review and no undo/automatic selection.

## B: timeline/playback (`playback.ts`)

The additional `paused` event reports transport state only, including programmatic stops. It never starts review. Handle drags preserve the pointer grab offset and viewport scrolling.

`PlaybackAdapter` owns the WaveSurfer lifecycle and emits `PlaybackEvent` to the composition layer. `load` accepts a webview-loadable URL supplied by the project repository. `pause('user')` signals an explicit user transport pause; `pause('programmatic')`, seeking, loading, and loop boundaries must not be translated into domain `user-paused`. Emit `ended` only for the end of a non-looping recording. `loop-boundary` is observational, never review entry. `selection-changed` describes a transient `TimeRange`; creating an annotation requires the app's explicit action. `annotation-selected` opens its note without seeking. Provide loop/zoom/fit and cleanup; listen/loop from an annotation are explicit composition commands. UI-specific marker drag and annotation update callbacks may be defined in the timeline-owned component interface, mapping to `update-anchor`.

The bundled fixture scope does **not** authorize arbitrary project recordings. Persistence and timeline owners must coordinate a narrow project-file asset scope or equivalent streaming mechanism and verify it in the real webview. Do not widen to the entire filesystem merely to make the smoke test pass.

## C: editor/notes/queue (`editor.ts`)

`EditorAdapter` binds an Editor.js document to a `NoteTarget` and a target-scoped monotonically increasing revision. Changes and `flush()` snapshots retain the target and revision that produced them. `open()` must flush and publish the outgoing snapshot before changing the target and resolve only when the incoming editor is ready. Serialize Editor.js async `save()` operations, or otherwise ensure a slower old serialization cannot publish as a newer revision; don't redirect late callbacks to a newly selected note. `flush` includes the most recent keystrokes. The composition layer accepts snapshots only when they are not older than that target's current revision and retains unsaved edits on failure.

The panels use domain state/actions, not an independent queue. Render first nonempty plain-text excerpt and timestamp as a derived label, using `Pending annotation` for unwritten pending items. Preserve Editor.js block JSON and support paragraphs, headings, lists, bold, italic and links. The integration layer is responsible for preventing global M and app-level undo while editing text. Flush before switching targets, completion, project switch, or save.

## D: project persistence (`persistence.ts`)

`ProjectRepository.create` copies the source WAV to a new project folder before returning `ProjectSession`; `open` validates and returns a `recordingUrl` that points to that copy, usable by the native webview. `directory` is runtime-only, permitting the whole project folder to move. A repository implementation must define its concrete on-disk metadata filename and communicate it to integration. Use native dialogs only with needed permissions, and preserve the original WAV.

`save(session, project, revision)` writes a full immutable snapshot. Revisions are monotonically increasing per open project, separate from per-note editor revisions. Serialize/coalesce writes without letting an older async save overwrite a newer revision; robustly replace metadata so interrupted writes do not truncate the old version. A resolved promise acknowledges that revision or a newer one is durable; errors reject and retain dirty content. Integration owns `SaveStatus`, flushes the current editor before taking a project snapshot, and keeps an edit dirty if it arrived during a write. Manual Save awaits flush and a write at least as new as the captured revision and does not complete/advance an item. Warn before close/switch when dirty or flush/save fails. Coordinate close protection and asset-scope capabilities with the orchestrator.
