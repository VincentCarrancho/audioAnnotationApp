# Note and queue integration

Exports: `src/features/notes` (`NotePanel`, `NotePanelHandle`, `createEditorAdapter`, `NoteEditorAdapter`, and label helpers) and `src/features/queue` (`QueuePanel`). These consume `DomainState` and emit `DomainAction`; neither owns queue state. Render the note panel below the timeline and the queue wherever the shell places review.

## Composition responsibilities

- Give `NotePanel` the selected note's current **target-scoped** revision and a stable `ref`. Subscribe via `onSnapshot` and synchronously record the snapshot by its **own** target and revision; reject older revisions for that target, update domain via `update-note`, and mark the project dirty. Do not infer a snapshot target from current selection. Snapshots can arrive during a transition. Per-target revision storage must be independent of disk-save/project revision. Reset that registry and remount `NotePanel` (for example with `key={project.id}` plus a session key if reopening the same project) after flushing when changing projects: project-note and annotation IDs are scoped to the current project session.
- Await `ref.current.flush()` before manual/autosave snapshots, project switch/close/unmount, completion, deletion, or any external action/effect that may replace or discard the editor. Capture the returned snapshot synchronously in composition before serializing project data, even if React state updates have not committed. `onSnapshot` also receives that snapshot. Do not complete/advance on save. If there is no selected/open note, composition's flush helper should resolve without calling `flush()`; it rejects if there is no editor. A failure must block the transition/save, preserve the editor, and remain visible.
- `NotePanel` flushes before its own navigation/delete actions; `QueuePanel.beforeAction` must be an async composition helper that flushes if an editor is open. Composition still guards all other entry points, including timeline selection, pause/review transitions, and project switching. Dispatch actions/effects only after the flush succeeds, using a synchronous current-state store/ref to prevent an outgoing snapshot from being lost to React batching. Forward failures to the shell's save/unsaved-change UI using `onError`.
- The adapter automatically flushes before switching targets; same-target opens are no-ops and never reset the caret. Avoid unmounting the panel while a flush is pending. The adapter is tied to its holder and cannot retain an editor after unmount. Opening failures leave the previous editor intact but hidden while the requested target differs; display the error and let composition recover or retry without dropping its content.
- `focusRequest` is an optional monotonically changing number. Increment it **only** on explicit note open/review (including paused capture), after selecting the intended target; it is not needed on passive capture or ordinary rerenders. Keeping the same number while another target is selected does not focus it. The editor never autofocuses. `ref.current.focus()` is also available for an explicit command. The app owns global M/Cmd+S handling and must exclude editor/contenteditable/form inputs so typing and text undo work normally.
- `QueuePanel.position` is the live playhead in seconds, used for `review-pending` and `select-queue-item`; do not supply an invented default. `onPlayAnnotation(id)` and `onLoopAnnotation(id)` are explicit composition callbacks: implement the desired seek/play or loop through the playback adapter. Navigation selection alone must not seek. The queue hides Done/Skip while the selected note is not its active review item, so these controls cannot complete a different hidden note.

## Checks

`npx vitest run src/features/notes src/features/queue` exercises a controlled asynchronous editor race, serialization failure, revisions and same-target behavior; labels; queue actions; and panel focus/navigation. Browser/native integration and actual Editor.js keyboard/tool behavior still require the integrated app verification.
